# نظام الإشعارات وإعادة التفاعل (E15)

> **المبدأ الحاكم:** الإشعار **معلوماتي فقط**. ليس مصدر سلطة للّعب أو المكافآت أو التقدّم أو المهام أو السلسلة.
> فتح إشعار أو قراءته أو النقر عليه **لا يمنح** XP ولا عملة ولا تقدّم مهمة ولا سلسلة ولا نقاط صدارة ولا محاولة إضافية.

## 1. القناة
**داخل المنصة (in-app) فقط.** لا Push خارجي (FCM/APNs/OneSignal/Web Push)، ولا SMS ولا WhatsApp ولا بريد تسويقي.
**لا SMTP مطلوب** و**لا Queue Worker مطلوب** و**لا Scheduler مطلوب لصحة اللعب** (راجع القسم 9).

## 2. بنية التخزين
- أُعيد استخدام جدول إشعارات Laravel القياسي (`User` يستخدم `Notifiable` أصلًا لكن الجدول لم يكن موجودًا) بترحيل جديد.
- ثلاثة أعمدة مخصَّصة: `type_key` و`category` (مفتاحا السجل المغلق) و`idempotency_key`.
- **قيد فريد** `(notifiable_type, notifiable_id, idempotency_key)` يمنع التكرار بنيويًا. لا بحث JSON للتفرّد.
- فهرس للصندوق `(notifiable_type, notifiable_id, read_at, created_at)` لعدّ غير المقروء والترتيب.
- التفضيلات: جدول `notification_preferences` (صف لكل مستخدم، أعمدة صريحة). غياب الصف = الافتراضيات (الكل مفعَّل).

## 3. الأنواع المنفَّذة (5) ومصدر كل منها

| النوع | الفئة | المصدر الحقيقي (Event source → type) | تذكير عودة؟ |
|---|---|---|---|
| `achievement_unlocked` | achievement | حدث مجال `AchievementUnlocked` يُطلَق **بعد commit** فتح الإنجاز (`AchievementService`) | لا (معاملاتي) |
| `streak_at_risk` | streak | المجدوِل الساعي على `player_streaks` | نعم |
| `daily_quests_available` | quest | المجدوِل الساعي على `player_streaks` + وجود مهام يومية قائمة | نعم |
| `security_password_reset` | security (**إلزامي**) | حدث Laravel الموجود `PasswordReset` | لا |
| `season_started` | season | حدث مجال `SeasonStarted` يُطلَق بعد commit أول مرة يصبح فيها الموسم مباشرًا (`SeasonLifecycleService`، القسم 13) | لا |

### مؤجَّل صراحةً (لا مصدر حقيقة يدعمه الآن - لا نخترع أحداثًا)
- **`season_ending_soon`:** مؤجَّل: لا حدث موثوق لاقتراب النهاية (النهاية `ends_at` بالحملة وتُحسَب عند العرض). يحتاج تصميمًا مستقلًا.
- **`campaign_available` / `campaign_stage_unlocked`:** بلا حدث نشر/إتاحة موثوق، ونمط "إشعار لكل خطوة" ممنوع.
- **`system_announcement`:** شريط الإعلان الداخلي (`announcement`) موجود ويؤدي الغرض - لا نكرره.
- **`quest_completed` / `weekly_goal_completed` / `streak_extended`:** واجهة اللعب تُخبر اللاعب فورًا؛ إشعار إضافي = ضجيج.
- **`weekly_goal_available`:** الأهداف الأسبوعية ظاهرة بصفحة `/quests`؛ تذكير أسبوعي ثالث يزيد الإزعاج بلا قيمة واضحة.
- فئات `store` و`engagement`: لا حدث يغذّيها فلا فئة.

## 4. السجلات المغلقة
`NotificationCategory` و`NotificationType` (PHP enums). لا فئة/نوع/أيقونة/رابط يأتي من الإدارة أو من قاعدة البيانات.
الوجهة الداخلية لكل نوع **ثابتة بالكود** (`allowedRoutes()`)، والمستدعي لا يملك تمرير مسار أصلًا.

## 5. الأمان
- **ملكية صارمة:** كل استعلام عبر علاقة المستخدم الحالي؛ معرّف إشعار غيره = 404. لا مسار إداري لقراءة صناديق اللاعبين، ولا CRUD إشعارات بـFilament.
- **لا HTML خام:** كل العرض بـ`{{ }}` (مُهرَّب). لا `{!!` ولا Script ولا iframe بأي حمولة.
- **لا روابط اعتباطية:** `NotificationUrlResolver` يقبل اسم مسار ضمن قائمة النوع حصرًا ومعاملات scalar، وينتج **مسارًا نسبيًا**. حمولة معدَّلة بقاعدة البيانات (رابط خارجي، مسار غير مسموح) = يُتجاهَل ويعود المستخدم للمركز.
- **لا GET يعدّل:** القراءة/الفتح/الحذف POST/DELETE بـCSRF.
- **لا أسرار:** لا كلمات مرور/توكنات/IP/بيانات محفظة. إشعار الأمان يستخدم بصمة HMAC غير قابلة للعكس كمفتاح تفرّد فقط.

## 6. التفضيلات والتحكم
ثلاث طبقات للإشعار الاختياري (كلها مطلوبة): المفتاح الشامل `notifications_enabled` **+** تفعيل التذكير المعني **+** تفضيل المستخدم - وتُقرأ **لحظة الإرسال** (لا لقطة قديمة).
- **الأمان إلزامي:** يتجاوز المفتاح الشامل وتفضيل المستخدم (لا عمود تفضيل له عمدًا).
- صفحة التفضيلات: `/notifications/preferences` (رابطها بالملف الشخصي وبمركز الإشعارات).
- إعدادات المنصة (تبويب «الإشعارات»، صلاحية `notifications.settings.manage`):

| المفتاح | الافتراضي |
|---|---|
| `notifications_enabled` | true |
| `streak_warning_enabled` | true |
| `streak_warning_hour` | 18 (بتوقيت المنصة UTC) |
| `min_streak_for_warning` | 2 |
| `daily_reminder_enabled` | true |
| `daily_reminder_hour` | 10 (UTC) |
| `max_reengagement_per_day` | 1 |

نفس عقد E14.1: الحفظ مقسَّم بالصلاحيات في الخادم، وحمولة معدَّلة من غير المصرَّح له تُتجاهَل، والتغييرات تُدقَّق (`notifications.settings.changed`).

## 7. سياسة إعادة التفاعل (Re-engagement)
**اليوم = تعريف E13 نفسه** (`QuestPeriodService`، المنطقة الزمنية للمنصة UTC، `now()` الحقيقي).
- **تحذير السلسلة:** سلسلة حيّة (`current_streak ≥ min_streak_for_warning`) وآخر نشاط مؤهِّل **أمس** (لم يتأهل اليوم) وساعة اليوم ≥ `streak_warning_hour`. مفتاح: `streak-risk:{user}:{Y-m-d}`.
- **تذكير المهام:** لاعب كان له نشاط مؤهِّل خلال آخر 7 أيام ولم يلعب اليوم، **وليس لديه سلسلة حيّة**، ضمن النافذة `[daily_reminder_hour, streak_warning_hour)`، ومع وجود مهام يومية قائمة فعلًا. مفتاح: `daily-quests:{user}:daily:{Y-m-d}`.
- **الأولوية:** تحذير السلسلة > تذكير المهام. تتحقق بثلاثة عناصر: (1) تقسيم الجمهور (صاحب السلسلة الحيّة لا يدخل جمهور تذكير المهام أصلًا)، (2) ميزانية اليوم، (3) قاعدة صريحة: لا تذكير مهام بعد تحذير سلسلة بنفس اليوم.
- **الميزانية:** `max_reengagement_per_day` لكل لاعب، تُحتسَب للتذكيرات فقط (الإنجازات والأمان لا تُحتسَب ولا تتأخر).
- **قراءة فقط من حالة اللعب:** المجدوِل يقرأ `player_streaks` ويسأل `QuestService::hasCurrentDailyQuests()` (دالة قراءة مضافة). **لا** ينشئ `UserQuestProgress` ولا يستدعي `syncCurrentQuests/progressFor/streakFor` ولا يعدّل السلسلة - فلا Side effect (لا إعادة لخلل E13 التاريخي).

## 8. الأمان من فشل الإشعار
الإشعار أثر جانبي ثانوي دائمًا:
- `AchievementUnlocked` يُطلَق عبر `DB::afterCommit` - فلا إشعار قبل نجاح المعاملة، وتراجع معاملة خارجية = لا حدث.
- `NotificationDispatcher` يلتقط كل استثناء ويُرجِع `Failed` ولا يرميه؛ والمستمعان يلتقطان أيضًا. فشل الإشعار لا يُراجع فتح إنجاز ولا مكافأة ولا مهمة ولا سلسلة.
- لا اعتماد على Queue: الإدراج متزامن خفيف (صف واحد). **لا تُنشأ Jobs.**

## 9. الجدولة والنشر
أمران مجدوَلان في `routes/console.php`:
- `notifications:dispatch-reengagement` - **ساعيًا** (`withoutOverlapping`). Idempotent: تشغيله 10 مرات = إشعار واحد. يعمل بـ`chunkById` (200 افتراضيًا) ويحمّل مستخدمي كل دفعة باستعلام واحد.
- `notifications:prune` - **يوميًا**: يحذف **المقروء** الأقدم من 90 يومًا فقط (غير المقروء لا يُمَس أبدًا).

للتفعيل على الخادم (نمط Laravel القياسي):
```
* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1
```
**غياب المجدوِل لا يكسر المنصة:** لا تصل تذكيرات العودة فقط، ولا فساد للعب أو السلسلة أو المهام. ولا نقول للاعب "أُرسِل" شيئًا لم يُنشأ؛ التذكير إشعار داخلي يظهر عند الدخول بعد إنشائه.

## 10. الواجهة
- جرس بشريط التنقل (مكوّن `x-notification-bell`): عدّاد غير مقروء (`99+` فوق 99) + قائمة منسدلة بآخر 5. **استعلامان فقط** لمستخدم موثَّق، ولا شيء للضيف/غير الموثَّق.
- صفحة `/notifications`: ترقيم (15)، فلترة (الكل/غير المقروء/فئة)، تعليم مقروء/الكل، حذف، حالة فارغة، وقت نسبي بالعربية + مطلق.
- لا WebSockets ولا Polling: يتحدّث العدّاد عند تحميل/تنقّل الصفحة.
- إتاحة الوصول: `aria-label` بعدد غير المقروء، `aria-expanded`، إغلاق بـEscape، تركيز مرئي، دعم RTL.

## 11. التحليلات
`NotificationAnalyticsService`: المُنشأ والمقروء ونسبة القراءة بحسب النوع (تجميعي فقط، بلا هوية، ولا ادّعاء نقرات). **واجهة إدارية: مؤجَّلة**؛ تُضاف صلاحية `notifications.analytics.view` عند بنائها فقط حتى لا تكون صلاحية بلا تنفيذ.

## 12. إضافة نوع جديد مستقبلًا
1) أضف case بـ`NotificationType` (فئة، أيقونة، مسار داخلي مسموح، نصوص).  
2) أضف مصدره الحقيقي (حدث مجال أو جدولة) **بمفتاح دلالي حتمي**.  
3) مرّره عبر `NotificationDispatcher::dispatch()` فقط.  
4) أضف اختبار تكرار/تفضيل/عزل فشل. لا تستدعِ `$user->notify()` من متحكّم.

## 13. بدء الموسم (`season_started`)
**تعريف "الموسم مباشر الآن" في موضع واحد فقط:** `SeasonLifecycleService::isLive()` = الموسم منشور + حملته متاحة بتعريف `CampaignProgressService::isCampaignAvailable` نفسه الذي يعتمده اللعب وصفحة المواسم (مفعَّلة، `starts_at` ليس بالمستقبل، `ends_at` ليس بالماضي). النشر وحده لا يعني البدء (المواسم «قريبًا» تظهر تسويقيًا).

**الانتقال ذري ويُسجَّل مرة واحدة:** `UPDATE seasons SET went_live_at = now() WHERE id = ? AND went_live_at IS NULL`. لا يُطلَق `SeasonStarted` إلا إن تأثّر صف فعلًا بهذا الاستدعاء، وبعد commit (`DB::afterCommit`). فالتشغيل المتكرر وإعادة المحاولة والسباق = حدث واحد على الأكثر. إيقاف/تفعيل الموسم أو حملته لاحقًا **لا** يعيد الحدث (`went_live_at` لا تُكتَب ثانية).

**من يستدعي المزامنة:**
- خطاف حفظ `Season` عند تغيّر `is_published` (أو إنشاء موسم منشور).
- خطاف حفظ `Campaign` عند تغيّر `is_active` أو `starts_at` أو `ends_at`.
- الأمر المجدول `seasons:sync-live-state` (كل 5 دقائق) لالتقاط البدء الناتج عن **مرور الوقت** - وهو المسار الوحيد له لأنه لا يكتب شيئًا بقاعدة البيانات. لا منطق بالأمر: يستدعي الخدمة نفسها. بغياب المجدوِل يُلتقَط البدء عند أول حفظ إداري لاحق فقط.
- تعديل مباشر بالاستعلامات (`Model::where()->update()`) يتجاوز الخطافات، والمجدوِل شبكة أمانه.

**الإشعارات:** `SeasonStarted` ← مستمع يبدأ سلسلة Jobs `DispatchSeasonStartedChunk` (دفعات `chunk_size`، مؤشر id، لا Job ضخمة ولا حلقة متزامنة داخل طلب الإدارة). الجمهور: مستخدمون **موثَّقون وغير مجمَّدين**. مفتاح التفرّد `season-start:{season}:{user}` + القيد الفريد = إشعار واحد لكل مستخدم/موسم حتى لو أُعيدت الدفعة. التفضيل (`season_enabled`) والمفتاح الشامل يُفحصان لحظة الإرسال. الوجهة `seasons.show` برابط الموسم (slug) فقط. لا XP ولا عملة ولا تقدّم مهام ولا سلسلة ولا مكافأة.

**Queue:** توزيع الإشعارات على المستخدمين يعمل عبر الصف. بـ`QUEUE_CONNECTION=sync` (محليًا) يعمل فورًا؛ بـ`database` يلزم عامل (`php artisan queue:work`) وإلا بقيت الـJobs في جدول `jobs` ووصلت عند تشغيله (لا ضياع). **بدء الموسم نفسه (`went_live_at`) لا يعتمد على الصف**، ولا اللعب.

**الترحيل والمواسم القديمة:** `went_live_at` تُعبَّأ رجعيًا **بلا أحداث ولا إشعارات** لكل موسم بدأ فعلًا قبل الترحيل (منشور + حملة مفعَّلة + `starts_at` ليس بالمستقبل، سواء ما زال مباشرًا أو انتهى - حتى لا يُنبَّه أحد بموسم قديم، ولا عند تمديد `ends_at` لموسم منتهٍ). المواسم القادمة/غير المنشورة/غير المفعَّلة تبقى `null` وتُنبَّه عند بدئها الفعلي الأول.
